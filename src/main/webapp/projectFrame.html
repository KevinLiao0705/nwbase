Critical Runtime Endpoints

  • /: JSP entry, loads and prints root.html content.
  • /hello: Servlet endpoint for command-style JSON POST requests.
  • Embedded mode: App.java launches Tomcat and maps HelloServlet.
  • Web assets: Served from src/main/webapp and packed into ROOT.war.

Frontend Module Layers

root.html loader core utilities (KvLib) UI composition (Block) domain widgets (lineChart / plot) system glue (MySystem / Server)
  • root.html loads many scripts in strict order.
  • onLoad calls sys.indexLoaded() to start runtime.
  • Block.js appears as layout/component construction backbone.

Backend Layer Notes

  • HelloServlet handles GET and command-style POST JSON.
  • Root initializes environment, logging, DB, and parameter maps.
  • GB acts as shared global holder for runtime/system variables.
  • SQLite is initialized via Root.dbConnect and para table checks.

External Dependencies

  • jakarta.servlet-api 6.0.0 (provided)
  • tomcat-embed-* 10.1.55
  • org.json
  • sqlite-jdbc
  • log4j2 + log4j 1.2 compatibility bridge

Request/Data Flow (High Level)

1) Browser requests / -> index.jsp runs.
2) index.jsp sets GB context and instantiates Root(request headers, webRootPath).
3) Root performs init: logging, setdata.xml, SQLite sync, network/machine info.
4) index.jsp reads root.html and returns full frontend page.
5) root.html loads JS modules; sys.indexLoaded() composes UI via Block/KvLib.
6) Frontend command calls go to /hello and receive JSON response.

Hotspots and Maintenance Tips

  • Script load order in root.html is fragile; changing order may break runtime init.
  • Global shared state (GB + many global JS vars) increases coupling across modules.
  • HelloServlet is a large command router; splitting handlers by action would improve maintainability.
  • Mixed legacy/new chart pages coexist (lineChart.js and echarts-*.html); align one strategy over time.
  • Current packaging and deployment path are coherent for Tomcat root context.
